# Plan 02-02: Server & Registry Integration

<objective>
Wire the new `EMLFormulaDB` into the MCP server and registry module. Replace all direct `KNOWN_FORMULAS` dict lookups with DB-backed calls. Keep builder functions as pure mathematical constructors in `registry.py`. Persist verification results to DB.
</objective>

## Task 3: Create get_db() singleton and wire into server.py

<read_first>
- src/eml_mcp/server.py (all 6 tool functions, how they use KNOWN_FORMULAS)
- src/eml_mcp/database.py (EMLFormulaDB API)
- src/eml_mcp/trees.py (EMLNode.from_dict for deserialization)
</read_first>

<action>
In `src/eml_mcp/server.py`:

1. **Remove** the import of `KNOWN_FORMULAS` from `eml_mcp.registry`.
2. **Add** imports:
   ```python
   import json
   from eml_mcp.database import EMLFormulaDB
   from eml_mcp.trees import EMLNode
   ```
3. **Create** a module-level DB singleton:
   ```python
   _db: EMLFormulaDB | None = None

   def get_db() -> EMLFormulaDB:
       """Get or create the database singleton."""
       global _db
       if _db is None:
           _db = EMLFormulaDB()
       return _db
   ```

4. **Update `eml_list_formulas`** tool:
   Replace `KNOWN_FORMULAS` iteration with `get_db().list_formulas()`. Map the DB rows into the same response format:
   ```python
   def eml_list_formulas():
       db = get_db()
       rows = db.list_formulas()
       formulas = {}
       for row in rows:
           formulas[row["name"]] = {
               "description": row["description"],
               "depth": row["depth"],
               "K": row["k"],
               "leaf_count": row["leaf_count"],
               "variables": json.loads(row["variables"]),
               "expression": row["expression"],
               "rpn": row["rpn"],
           }
           if row.get("note"):
               formulas[row["name"]]["note"] = row["note"]
       return {
           "formulas": formulas,
           "total": len(formulas),
           "grammar": "S → 1 | eml(S, S)",
           "reference": "Odrzywołek (2026), arXiv:2603.21852v2",
       }
   ```

5. **Update `eml_tree_info`** tool:
   Replace `KNOWN_FORMULAS` lookup with `get_db().get_formula(formula_name)`. Deserialize tree with `EMLNode.from_dict(json.loads(row["tree_json"]))`:
   ```python
   def eml_tree_info(formula_name, evaluate_at=None):
       db = get_db()
       row = db.get_formula(formula_name)
       if row is None:
           available = [r["name"] for r in db.list_formulas()]
           return {"status": "error", "message": f"Unknown formula '{formula_name}'", "available": available}

       tree = EMLNode.from_dict(json.loads(row["tree_json"]))
       variables = json.loads(row["variables"])
       # ... rest of the logic stays the same, using tree and variables ...
   ```

6. **Update `eml_verify`** tool:
   - Replace `KNOWN_FORMULAS` lookup with `get_db().get_formula(formula_name)`
   - After computing verification results, persist to DB:
     ```python
     db.add_verification(
         formula_name=formula_name,
         passed=result["passed"],
         max_error=result["max_error"],
         tolerance=tolerance,
         n_tests=result["n_tests"],
         details=result["details"],
     )
     ```
   - Change `readOnlyHint` annotation to `False` since it now writes to DB

7. **Update `eml_compile`** tool:
   - Replace `KNOWN_FORMULAS` direct lookup with `get_db().get_formula(expr)`
   - For alias resolution, use DB lookup: `get_db().get_formula(alias_map[expr])`
   - Keep composition logic (exp(exp(x)) etc.) as-is since it uses builder functions
   - Retain imports: `build_exp_tree`, `build_exp_from_subtree`, `build_ln_tree`, `build_ln_from_subtree` from registry — these are still needed for composition

8. **Keep** the `eml_evaluate` tool unchanged (it doesn't use the registry at all).
9. **Keep** the `eml_master_tree` tool unchanged (it calls `build_master_tree` directly).
</action>

- `src/eml_mcp/server.py` contains `from eml_mcp.database import EMLFormulaDB`
- `src/eml_mcp/server.py` contains `def get_db()`
