# Requirements Archive: v1.0 (Foundation)

**Archived:** 2026-04-16

## v1 Requirements (Complete)

### Package Structure
- [x] **PKG-01**: Project restructured as `src/eml_mcp/` Python package with `__init__.py` and submodules
- [x] **PKG-02**: `eml_core.py` split into focused submodules (operator, trees, registry, verification)
- [x] **PKG-03**: `server.py` split into MCP tool handlers and server configuration
- [x] **PKG-04**: All existing MCP tools work identically after restructure (no breaking changes)
- [x] **PKG-05**: `pyproject.toml` updated with new package path and entry points

### Persistence
- [x] **DB-01**: SQLite database stores formula definitions (name, description, tree structure, complexity K, leaf count)
- [x] **DB-02**: Database stores derivation provenance (which formulas were composed to derive a new one)
- [x] **DB-03**: Database stores verification results with timestamps (formula, test points, errors, pass/fail)
- [x] **DB-04**: Database stores symbolic regression results (master tree weights, snap results, target function)
- [x] **DB-05**: Hardcoded `KNOWN_FORMULAS` dict replaced by DB-backed registry; only irreducible seeds (constant 1, EML operator) remain in code
- [x] **DB-06**: Database auto-initializes with seed formulas on first run (migration from current hardcoded set)

### AST & Compiler
- [x] **AST-01**: Expression parser handles standard mathematical notation (`"exp(x)"`, `"sin(x)"`, `"x + y"`, `"x * y"`, `"x^2"`)
- [x] **AST-02**: Parser produces a typed AST with nodes for constants, variables, unary ops, binary ops
- [x] **AST-03**: Compiler resolves AST nodes to known EML tree fragments from the DB registry
- [x] **AST-04**: Compiler composes EML tree fragments to build complete trees for compound expressions
- [x] **AST-05**: Compiler reports when a requested function has no known EML decomposition (rather than failing silently)

### Formula Discovery
- [x] **DISC-01**: Discovery engine can compose two existing formulas via the EML operator and evaluate the result
- [x] **DISC-02**: Discovery engine numerically verifies candidate compositions against reference functions
- [x] **DISC-03**: Discovery engine persists verified formulas to DB with full provenance
- [x] **DISC-04**: Discovery engine tracks complexity (K = leaf count) and prefers shorter trees when multiple derivations exist
- [x] **DISC-05**: Discovery engine can be invoked via MCP tool to explore the formula space on demand
- [x] **DISC-06**: Discovery engine preserves and persists mathematically valid but non-target emergent formulas (Novelty Search)

### MCP Tools
- [x] **MCP-01**: New `eml_db_search` tool searches formula DB by name, complexity, or tag
- [x] **MCP-02**: New `eml_db_derive` tool composes formulas and verifies/persists results
- [x] **MCP-03**: New `eml_db_history` tool retrieves verification history for a formula
- [x] **MCP-04**: Existing `eml_evaluate`, `eml_tree_info`, `eml_verify`, `eml_compile`, `eml_master_tree`, `eml_list_formulas` tools updated to use DB backend
- [x] **MCP-05**: All MCP tool responses remain structured JSON suitable for AI agent consumption

### Testing
- [x] **TEST-01**: pytest test suite covering all 8 existing formulas (evaluate, verify identity)
- [x] **TEST-02**: Tests for DB operations (CRUD, migration, seed initialization)
- [x] **TEST-03**: Tests for AST parser (valid expressions, error cases, edge cases)
- [x] **TEST-04**: Tests for compiler (known decompositions, unknown function handling)
- [x] **TEST-05**: Tests for discovery engine (composition, verification, persistence)
- [x] **TEST-06**: Tests for MCP tool surface (tool registration, input validation, response shapes)

### CI/CD
- [x] **CI-01**: GitHub Actions workflow runs on push and PR
- [x] **CI-02**: CI runs `trunk check` (ruff, black, isort)
- [x] **CI-03**: CI runs `pytest` with coverage reporting
- [x] **CI-04**: CI fails on lint errors or test failures

## Requirement Outcomes
All v1 requirements were validated by automated tests and E2E verification during Phase 4.
- **Adjustments:** PKG-02 was expanded to include `primitives.py` for irreducible fragments.
- **Dropped:** None.
- **Deferred:** Structural similarity (Tree Edit Distance) was deferred to v2.
